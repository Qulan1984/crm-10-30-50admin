# Apps Script backend для CRM

Этот файл описывает, как развернуть свой собственный Google Apps Script backend для CRM. Нужно сделать один раз, потом просто работает.

## Шаг 1. Создать Google Sheet

1. Открой https://sheets.new — создастся новый пустой Google Sheet.
2. Назови его, например, `CRM 10-30-50`.
3. Создай (или переименуй первый) лист с именем **ровно** `funnel` — это лист воронки.
4. (Опционально) Добавь листы `Потенциальные`, `Сделка`, `КХ` — это «другие» списки. Если их нет, CRM создаст автоматически при первом сохранении.
5. **Не создавай** лист `Messages` — Apps Script создаст его сам при первом входящем WhatsApp-сообщении.

## Шаг 2. Создать Apps Script проект

1. В Google Sheet → меню **Расширения → Apps Script**. Откроется редактор скриптов, привязанный к этой таблице.
2. Слева увидишь файл `Код.gs` (или `Code.gs`). Открой его — там будет пустая функция `myFunction`.
3. Удали всё содержимое.
4. Скопируй содержимое файла `apps-script/Code.gs` из этого репозитория и вставь.
5. Нажми **Сохранить** (иконка дискеты или `Cmd+S`). Дай проекту имя, например `CRM Backend`.

## Шаг 3. Задеплоить как Web App

1. В редакторе Apps Script сверху справа нажми **Развернуть → Новое развёртывание** (Deploy → New deployment).
2. Шестерёнка слева → выбери тип **Веб-приложение** (Web app).
3. Заполни:
   - **Описание**: `CRM v1` (любое)
   - **Запуск от имени**: `Я (твой email)`
   - **Доступ**: **`Все`** (Anyone) — это критично, иначе бот не сможет писать без авторизации.
4. Нажми **Развернуть**. Google попросит подтвердить доступы → разреши (это твой собственный скрипт к твоей собственной таблице, безопасно).
5. После деплоя получишь **URL веб-приложения** вида:
   ```
   https://script.google.com/macros/s/AKfycby_XXXXX/exec
   ```
   **Скопируй этот URL — он понадобится в двух местах.**

## Шаг 4. Прописать URL в боте

Открой `Example/bot.ts` и замени:

```ts
const GS_URL = process.env.GS_URL || 'PASTE_YOUR_APPS_SCRIPT_URL_HERE'
```

на свой URL. Либо запускай через переменную окружения:

```bash
GS_URL='https://script.google.com/macros/s/AKfycbwNCnfHq5L1RBt1rOF-MG6cjrl9hsqMKArdYC5FR_Xb6L-CENsi3s3P_B3EbcN_3bWx/exec' yarn bot
```

## Шаг 5. Прописать URL в CRM

Открой `index.html`, найди строку (~598):

```js
const GS_URL = 'https://script.google.com/macros/s/AKfycbwl.../exec';
```

И замени URL на свой. Закоммить и запушь — GitHub Pages обновится через минуту-две.

## Проверка endpoints вручную

После деплоя можешь руками проверить, что backend живой:

- В браузере открой `<твой URL>?action=readFunnel` — должен вернуть `{"funnel":[]}` или с данными.
- В терминале:
  ```bash
  curl -L "<твой URL>?action=pollMessages&since=0"
  # → {"messages":[]}
  ```

## Обновление кода

Если меняешь `Code.gs` — нужно сделать **новый деплой** (или обновить существующий через **Развернуть → Управление развёртываниями → Карандаш → Новая версия**). URL **не меняется**, если обновляешь существующий деплой.

## Что внутри Code.gs

| Action | Метод | Что делает |
|---|---|---|
| `readFunnel` | GET | Возвращает все строки листа `funnel` |
| `readOther` | GET | Возвращает все листы кроме `funnel` и `Messages` |
| `pollMessages` | GET | Возвращает сообщения с `timestamp > since` |
| `writeAll` | POST | Перезаписывает листы `funnel` + `other` (CRM сохраняет данные) |
| `addMessage` | POST | Добавляет строку в `Messages`, помечает `isNewLead` если телефон новый |

Все операции защищены `LockService` от гонок при параллельных запросах.

# Телефония Beeline KZ (история звонков, статусы, записи)

CRM подтягивает звонки из «Виртуальной АТС» Beeline KZ (`cloudpbx.beeline.kz/VPBX`).

**Важно про API.** У казахстанской ВАТС **нет публичного REST API** (хост `cloudpbx.beeline.kz/apis/portal/` отдаёт 404; раздела «Настройки → API» в портале тоже нет — это другая, более старая платформа, чем российская `cloudpbx.beeline.ru`). Поэтому официальных вебхуков `BASIC_CALL` здесь не существует.

Вместо этого Apps Script работает как **неофициальный клиент к самому порталу**: логинится логином/паролем, получает сессионную куку `BearerToken` и дёргает те же внутренние эндпоинты, что использует веб-интерфейс портала. Это **только чтение**. «Статусы через вебхук» заменены на периодический опрос журнала по триггеру.

Используемые эндпоинты портала (выяснены реверсом UI):

| Назначение | Запрос |
|---|---|
| Вход | `POST /VPBX/Account/Login` → кука `BearerToken` |
| Журнал звонков | `POST /VPBX/Stat/CallLog?query.ProfileID=<pid>` |
| Список записей | `POST /VPBX/Cloud/CallRecord?query.ProfileID=<pid>` |
| Аудио записи | `GET /VPBX/Cloud/GetCallRecordContent?asPreview=false&id=<recId>` |

Звонок и его запись связываются по полю `CallID`.

## Шаг 1. Узнать ProfileID

1. Зайди в портал: https://cloudpbx.beeline.kz/VPBX/Profile/Summary
2. В адресной строке любой внутренней страницы будет `?profileID=XXXX` (например `2991`). Это и есть `BEELINE_PROFILE_ID`.

## Шаг 2. Прописать Script Properties

В редакторе Apps Script: **Настройки проекта (шестерёнка) → Свойства скрипта**:

| Свойство | Значение |
|---|---|
| `BEELINE_LOGIN` | логин от портала |
| `BEELINE_PASSWORD` | пароль от портала |
| `BEELINE_PROFILE_ID` | `profileID` из шага 1 |
| `BEELINE_BASE` | (опц.) `https://cloudpbx.beeline.kz/VPBX/` — значение по умолчанию |

> Пароль хранится на стороне Apps Script (в твоём проекте), не в репозитории и не в браузере. Если меняешь пароль на портале — обнови это свойство. Кука кешируется на ~25 минут и обновляется автоматически.

## Шаг 3. Проверить вход

В редакторе выбери функцию `testBeelineLogin` → **Выполнить**, разреши доступы. В `Просмотр → Журналы` должно появиться что-то вроде `{"calls":N,"records":M}`.

## Шаг 4. Триггер опроса

1. Слева **Триггеры (будильник) → Добавить триггер**.
2. Функция: `syncBeelineCalls`, событие: **По времени → Каждую минуту** (или каждые 5 минут).

Скрипт за каждый прогон тянет журнал и записи за последние 3 дня (`BEELINE_LOOKBACK_DAYS`) и upsert'ит их в лист `Calls` по `callId` (повторы безопасны).

## Что появляется в таблице

Лист **`Calls`** (создаётся сам):
`callId | timestamp | direction | phone | abonent | status | duration | recordId | comment | updatedAt`

`updatedAt` — курсор опроса (двигается при любом изменении строки), `timestamp` — реальное время звонка. CRM поллит по `updatedAt`, поэтому появившаяся позже запись (`recordId`) долетает до карточки.

## Эндпоинты Apps Script (для CRM)

| Action | Метод | Что делает |
|---|---|---|
| `pollCalls&since=<ms>` | GET | звонки с `updatedAt > since` (CRM поллит каждые 10 c) |
| `callRecording&id=<recordId>` | GET | проксирует аудио из портала, отдаёт `{mime, b64}` для `<audio>` |

## Проверка вручную

```bash
curl -L "<твой /exec URL>?action=pollCalls&since=0"   # -> {"calls":[...]}
```

Если `pollCalls` пуст — запусти `syncBeelineCalls` руками и посмотри `Просмотр → Журналы` на ошибки (чаще всего неверный логин/пароль или `ProfileID`).
